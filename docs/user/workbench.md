# 工作台

`awkit ui` 在你的電腦上開一個網頁，看工作進行到哪裡：每張工單在哪一站、哪裡卡住要你出手、engine（派工的程式）、執行者和審查做了什麼，以及 `awkit doctor` 的檢查結果。不用開終端機也看得到全部。

規劃也在工作台裡做：開新的規劃、看議會開會、開會時插話或暫停、改議程、回答議會的問題、改或刪工單、核可。開始與停止工作也是：見下面的「執行」。

---

## 打開

在專案資料夾裡：

```bash
awkit ui
```

它會印出一個網址並打開瀏覽器：

```
AWK workbench: http://127.0.0.1:4747/?token=…
Press Ctrl+C to close it. Work that is going on goes on.
```

| 選項 | |
|---|---|
| `awkit ui <資料夾>` | 加入另一個專案，不必先切到那裡 |
| `--port N` | 用另一個埠；預設 4747，被占用時自己換一個空的 |
| `--no-open` | 只印網址，不開瀏覽器 |

關掉工作台（Ctrl+C 或關掉終端機）不會停下正在跑的工作，也不會停下議會正在開的會。工作做完（只剩需要你處理的工單也算）、或有人要它停（工作台的「停止」或 `awkit stop`），工作才會停；會開完、或你在工作台按「暫停」，會才會停。

## 誰打得開

- 只聽 `127.0.0.1`：同一個網路的其他電腦連不到。
- 每次啟動有一把新的鑰匙，在印出來的網址裡（`?token=…`）。用那個網址打開之後，鑰匙存在這個瀏覽器的 cookie，網址列上的鑰匙會被拿掉。
- 重開 `awkit ui` 之後，舊的分頁就不認得了，會說「要用 awkit ui 給的網址打開」：改用新印出的網址。
- 別的網站的網頁不能叫工作台做事：工作台只接受自己頁面送來的變更。

## 裡面有什麼

| 頁面 | 看什麼 |
|---|---|
| 總覽 | 工作路線：需求、議會、工單、寫程式、審查、合併。每張工單是線上的一個小牌子，卡住的岔到黃色側線。下面是要你處理的事、剛剛發生的事、合併了幾張、這一輪的狀態、里程碑 |
| 需要你處理 | 卡住的工單（審查幾次都沒過，或執行者做不下去）；在等你的規劃：議程要你看、問題要你答、會停下來要你接著開、工單等你核可；被擋下、等你決定的教訓；`awkit status` 的提醒 |
| 規劃與議會 | 每一份規劃和它的會走到哪；開新的規劃。見下面的「規劃」 |
| 工作看板 | 每張進行中的工單，依階段分欄；點開看它的經過、在等哪張、GitHub 上的工單與 PR；沒在工作時可以「只做這張」 |
| 執行 | 開始工作、停止工作，engine 正在做哪一步、每張工單走到哪，執行者現在在說什麼。見下面的「執行」 |
| 活動紀錄 | 這一輪的每一步：engine 把每張工單從哪一步移到哪一步、收到的停止、和主控的比對，執行者、審查與解衝突做了什麼（花了多久、多少錢），防護擋下或標記的內容與你對它們的決定。可以只看 engine、執行者、審查、防護，或只看警告與錯誤；用 `AWKIT_ENGINE=principal` 跑的一輪另有「主控」 |
| 教訓 | 審查教給 AI 的事：使用中的、被擋下等你決定的、已停用的。見下面的「教訓」 |
| 設定 | 議會由哪些角色組成，以及專案怎麼建置、測試、審查。見下面的「設定」 |
| 健康檢查 | 和 `awkit doctor` 同一套檢查 |
| 你的專案 | 加入或移出專案；移出只是不在清單裡，資料夾不會動 |

畫面會自己更新：工作推進時，卡片自己移動，紀錄自己長出來。GitHub 上的工單每 30 秒問一次；要馬上問，按總覽的「重新問 GitHub」。

黃色只用在一件事：要你出手。看到黃色，就是有事只有你能決定。

`Ctrl K` 搜尋頁面與工單，`?` 打開說明，`Esc` 關閉視窗。

## 規劃

和 `awkit plan` 是同一場會，只是在網頁上開、在網頁上看。一個專案一次開一場會：每場會都會改同一份決策紀錄（`docs/decisions.md`）和文件。

**開新的規劃。** 在「規劃與議會」按「開新的規劃」，寫下你想做什麼，像跟同事交代事情：給誰用、最重要的是什麼、哪些這次不做。兩個選項：

- **先問我只有我答得出來的問題**（預設勾著）：開始討論前，議會列出只有你知道答案的事，等你答完才開始。留白的，議會先假設，會後給你確認。不勾的話，全部由議會先假設。
- **議程排好先給我看**：主持人排好議題後先停下來，等你看過、改好再開始。

開會會呼叫 Claude；議題越多，花的越多。一場會最多幾個議題、幾次呼叫，寫在 `.ai/roster.yaml` 的 `limits`。

**開會中。** 畫面上是圓桌：這一題誰主講、誰發言、現在輪到誰；下面是這一題的經過，有人說完就長出來。長的發言先收起，按「看全文」展開。點上面的議題可以回頭看談過的題目。

- **說話**：在「你想說什麼」寫下來送出。你的話跟需求一樣算數。正在發言的角色說完後，下一個發言的角色就會聽到；已經裁定的事，負責裁定的角色會照你的話把所有決策重審一遍，受影響的文件由負責的角色整份重看。談過的議題不會重談。
- **回答問題**：說話時可以選「這是在回答哪個問題」，議會就知道哪個假設有答案了。
- **暫停**：正在發言的角色說完這一段就停，說過的都留著。暫停時可以先說話，或改還沒談的議題；按「接著開會」從停下的地方繼續，說過的不會重來。

會停下來的情況還有兩種：**中斷了**（開會的程序不在了，例如電腦重開）和**停住了**（遇到錯誤，例如 Claude 暫時沒回應）。兩種都按「接著開會」，從停下的地方繼續。

**開完了。** 分成幾頁：

| 頁 | |
|---|---|
| 工單 | 這次擬的工單和里程碑。每張工單標出風險（低、中、高），展開看得到它會動到的路徑。核可前可以改標題、內容、範圍、會動到的路徑、風險、驗收條件，也可以刪掉不要的（別張工單要等它做完的，要先刪那一張）。路徑寫錯（不是合法的寫法、不在工單的 repo 資料夾裡、包括工作流程自己的檔案）存不起來，會說是哪一條。按「核可」之後的步驟見下面。**issue 建了就刪不掉，只能關掉** |
| 決策 | 現行的決策，依議題分；被取代或撤回的另外收著；你說話之後的每一次重審 |
| 假設 | 議會替你先假設的事。按「回答」寫下答案，再按「照我的話重審」：決策照你的答案重審，工單重排。議題不會重談 |
| 文件 | 這次寫了哪些文件、誰負責，還有和專案規則不符、還沒改好的地方 |
| 會議經過 | 每一題的完整經過 |

**核可。** 議會寫的文件（決策紀錄、各角色的文件、工單清單）一開始只在你電腦上的專案資料夾裡。執行者是從整合分支（例如 `develop`）開始做事的，看不到它們；`awkit run` 也只從乾淨的資料夾開工。所以「核可」會依序做這些事，每一步都顯示在頁面上：

1. 檢查：專案裡沒有工作在跑、沒有別的會在開，GitHub 上有整合分支。
2. 在 GitHub 建工單，**先不掛工作標籤**：這時執行者還不會動它們。
3. 把議會寫的文件放進一個新分支（`feat/plan-<規劃>`），開成 PR。送的是 `docs/` 底下（和名冊放在別處的角色文件）所有還沒 commit 的東西：每場會共用同一份決策紀錄和文件，分不開，所以另一份還沒核可的規劃寫的文件也會一起送出。你資料夾裡的其他東西不會被動到。
4. 等 PR 的 CI；過了就合併進整合分支。專案沒有替 PR 跑的 CI 就直接合併。CI 沒過、專案有 CI 但 GitHub 沒替這個 PR 跑（例如 Actions 沒開或額度用完）、或 GitHub 規定要人審核，就停在這裡告訴你，不會繞過去。
5. 文件到了整合分支，才幫工單掛上工作標籤：執行者從這時起才會接這些工單。
6. 把你的專案資料夾更新到和整合分支一樣（資料夾要在整合分支上，而且每個檔案都要和剛合併進去的一模一樣，才會動它）。做不到時會說原因，什麼都不動。

停在半路時，修好原因再按「接著核可」，會從停下的那一步接著做，不會重建工單。關掉工作台，核可也照樣做完。

用終端機也一樣：`awkit plan approve <規劃> --merge-docs`。

工單核可之後，這份規劃就停在這裡；想改方向，開一個新的規劃，議會會讀這次的決策和文件接著規劃。

## 執行

和 `awkit run`、`awkit stop` 是同一件事，只是在網頁上按。

**開始工作。** 按「開始工作」，選「所有可以做的工單」或「只做一張」。engine 把工單交給執行者，寫好的程式經過審查才合併；預設一次一張，設定頁的「同時做幾件事」可以讓它同時做好幾張。有工單需要你時，只有那張停下來，其他的照做；做到沒有別的工單可做，就會停下。在工作看板點開一張還沒開始的工單，也可以直接「只做這張」。工作在另一個程序裡跑，關掉工作台也不會停。

**工作中。** 上面說 engine 正在做什麼：執行者在寫哪張工單、審查者在審哪個 PR、在解哪個 PR 的衝突、合併佇列在合併哪個 PR，從什麼時候開始；同時在做好幾件時，一件一行。頂端的「工作中」寫著工單編號，不只一張時寫幾張。停下來之後，說上一輪為什麼結束（做完了、你要它停、有工單需要你……）。

**每張工單走到哪。** engine 手上的每張工單一列，加上上一輪做完的：

- 它在哪一步（寫程式中、審查中、PR 有衝突、排隊合併、需要你、已合併……）、它的 PR、從什麼時候。審查通過、在等合併的，寫著排第幾個（「下一個合併」「排隊合併，第 2 個」）。
- engine 正在做的那幾張排在最前面，寫著現在誰在做。
- 重做過的，寫著試了幾次、最多幾次（例如「重新審查 1／3 次」「合併前的檢查沒過 1／3 次」）；到了上限就交給你。
- 需要你的那張是黃色，寫著為什麼。等你核可的高風險改動也是黃色，寫著為什麼是高風險，以及在終端機怎麼核可或退回（`awkit lane approve`、`awkit lane reject`）。
- 這一輪裡防護擋下或標記過它的內容，寫著是什麼、為什麼。

點一列打開那張工單。更早就結束的只算張數，經過在活動紀錄。

**和主控的比對。** 只在用影子模式（`AWKIT_ENGINE=shadow awkit run`）跑過之後出現：那一輪 engine 每做一個決定，舊的主控在旁邊算一次、只算不做。這裡寫比了幾步、幾步一樣、幾步是已知的差異、幾步不同，以及最近幾個不同的步驟兩邊各要做什麼。

開不了工的時候，按鈕會停用並說原因：有會正在開（它會改到工作要讀的文件）、有規劃正在核可、還沒有開著的工單，或開工前的檢查沒過（和健康檢查的「工作需要的」同一套；「Git Status」沒過通常是議會的文件還沒核可）。

**停止工作。** 兩種：

- **收尾後停**：手上正在做的事（執行者正在寫、審查正在審，或合併佇列正在合併）做完就停，不再接新的工作。和 `awkit stop` 一樣，最乾淨，但可能要等一陣子。
- **立刻停**：engine 馬上結束執行者、審查和正在進行的合併（連它們開出來的程式），再結束它自己。和 `awkit stop --now` 一樣。做到一半的改動留在執行者自己的工作區（`.worktrees/`），不會進 PR；下一輪會從那張工單重新開始。合併到一半的 PR 留在合併佇列，下一輪重新合併。留下的工作區可以在健康檢查清掉。

兩種都經由 engine 的收件匣交給它，頁面會說它收下了沒有。engine 十秒內沒有回覆「立刻停」時，工作台直接結束它的程序。`AWKIT_ENGINE=principal` 跑的主控沒有收件匣：收尾後停寫停止標記，立刻停直接結束它的程序。

**即時輸出。** 「這一輪」是從工作台開的那一輪在終端機會看到的內容，也就是 engine 派工的紀錄；「工單 #N」是那張工單的執行者說的話；用 `AWKIT_ENGINE=principal` 跑時另有「主控」。工作中每兩秒更新一次；往上捲看舊的內容時，不會被拉回最下面。

## 教訓

被審查退回、後來終於通過的變更，會濃縮成教訓，之後動到同樣檔案的執行者與審查者會看到相關的幾條。教訓是 AI 從審查的經過寫出來的，裡面可能夾帶別人寫的文字，所以給任何 AI 看之前都會先檢查：看起來像在下指令、要連到外面、或講到流程本身的權限與檔案的，就先隔離。

被隔離的教訓排在最上面，也會出現在「需要你處理」。每一條都列出被擋下的原因、它的全文（看不見的字元用 `<U+…>` 標出來）、從哪張工單來。讀完之後：

- **不採用**：停用它，不會再給任何 AI。
- **放行，讓它試用**：確認之後，它當成新的教訓試用，執行者讀到時會標明「未驗證」。

兩種決定都記在活動紀錄的「防護」裡，和終端機的 `awkit lessons approve`、`awkit lessons reject` 是同一件事。

## 設定

兩個分頁：

- **議會名單**（`.ai/roster.yaml`）：整場會議的語言、模型、想多深；每個角色的名稱、代號、立場、負責寫的文件、模型和想多深；誰負責裁定談不攏的事、誰負責排工單；一場會議的上限。專案還沒有名單時，顯示的是第一次開規劃會議會用的那一份，存檔就會把它加進專案。
- **專案設定**（`.ai/config.yaml` 裡常改的部分）：名稱與說明、每個 repo 的準備／建置／測試指令、誰來寫程式（Codex 或 Claude Code，後者可以選模型和想多深）、審查與解衝突（engine 的審查者和解衝突者各用哪一個工具、模型、想多深，一次最多跑多久、花多少；空著就是預設，預設跟著執行者，框裡寫出預設是什麼；審查者和執行者是同一個模型時會提醒你）、同時做幾件事（全部加起來最多幾件，以及 Codex、Claude Code 各自最多幾件；每個工具旁邊寫著現在哪些角色用它）、過關分數與合併方式、重試次數與指令的時限。分支和 repo 清單只能看：換分支要先在 GitHub 上建好，所以在終端機改。

欄位空著就是用預設值，框裡會寫預設是多少。改了的分頁上有一個點；有地方要改時，存檔鍵會停用，並說還有幾處。

**存檔不會直接改你資料夾裡的檔案。** 和核可一樣，工作台把修改開成一個 PR（分支 `feat/awk-settings`），CI 過了就合併進整合分支，再把你的專案資料夾更新到整合分支。改專案設定時，`awkit generate` 依設定產生的檔案（`CLAUDE.md`、`AGENTS.md`、CI workflow 等）會一起進這個 PR。修改套在 GitHub 上最新的設定檔上：你只改了測試指令，別人剛在 GitHub 上改的合併方式會留著；你改的地方別人也改了，就會停下來請你重新載入再改。關掉工作台也會繼續。

有工作正在跑、有會正在開、有規劃正在核可時，可以改但不能存；專案沒有連到 GitHub（沒有 origin）時也存不了。停在半路時，頁面會說原因：CI 沒過、GitHub 沒跑 CI、GitHub 不讓自動合併、程序被關掉。修好後按「再試一次」，會照同一個修改再做一次，PR 還開著就沿用它。

用終端機也一樣：`awkit settings apply --request <檔案>`，見 `awkit help settings`。

## 第一次打開

會先問你想怎麼認識工作台：

- **帶我走一遍**：8 步導覽，約 2 分鐘。`Esc` 是先停在這一步，下次接著看；方向鍵上一步、下一步。
- **跳過全部教學**：不再出現任何教學。跳過後幾秒內可以按「復原」。
- **不要導覽，只留上手清單**：側邊欄最下面有一份清單，做過的事會自己打勾。

之後隨時可以從右上角的「說明」重看導覽、打開上手清單、查名詞，或清除教學紀錄重新開始。

教學看到哪、清單做了哪些、加入了哪些專案，存在你自己的設定資料夾，不在專案裡，也不會上傳：

| 系統 | 位置 |
|---|---|
| Windows | `%AppData%\awkit\workbench.json` |
| macOS | `~/Library/Application Support/awkit/workbench.json` |
| Linux | `~/.config/awkit/workbench.json` |

環境變數 `AWKIT_WORKBENCH_SETTINGS` 可以指定另一個檔案。

## 從原始碼編 awkit

工作台的畫面在 `web/`，要先建好，`go build` 才會把它放進 awkit：

```bash
npm --prefix web ci
npm --prefix web run build      # 寫到 internal/workbench/dist/
```
